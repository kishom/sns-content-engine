# エビデンス検証ワークフロー（全テーマ共通の標準工程）

健康・医療テーマの台本は、**書いてから出典を探すのではなく、主張ごとに一次資料へ実際にアクセスして突き合わせる**。この文書はその手順書。次テーマ（犬の歯周病、猫の甲状腺機能亢進症 等）でそのまま使う。

**成果物:** 各テーマフォルダの `03-evidence.md`
**位置づけ:** `02-script` と `03-hook` の間に挟む**必須ゲート**。ここを通らない台本は `04-automate` の投稿キューに載せない。

```
02 SCRIPT ──▶ [ E. EVIDENCE ] ──▶ 03 HOOK ──▶ 04 AUTOMATE
                    │
                    └─▶ vet-marketing-compliance（表現チェック）
```

> エビデンス検証（**内容が正しいか**）と vet-marketing-compliance（**表現が安全か**）は別工程。
> 両方通す。片方では代替できない。「断定を避けた表現」であっても、**中身に根拠が無ければ出せない**。

---

## 0. 大原則

1. **出典の無い主張は、主張が無いことより悪い。** 一つの根拠なき断定が、そのアカウントが語る他のすべての信頼性を毀損する。
2. **後付け出典を作らない。** 主張 → 出典の順。逆順で作ると「一見それらしいが、実は何も担保していない引用」（→ §6 の IRIS 事例）が必ず混入する。
3. **アクセスできなかった資料を「確認した」と書かない。** 例外なし。
4. **対象種を必ず書く。** 犬の知見を猫に、人の知見を動物に、無断で持ち込まない。「ペット」と丸めない。
5. **確認できなかったときは「確認できなかった」と書く。** これは失敗の報告ではなく、工程の正常な出力。
6. **「誰もが知っている数字」ほど疑う（循環引用の罠）。** 権威ある二次資料が揃って同じ数字を出していても、
   一次研究に辿り着けないなら使わない。実例＝犬の歯周病「3歳以上の80%」は AVMA / Merck / Cornell / VCA が
   引用しているのに元の疫学研究が出てこず、資料間で **12.5%〜100%（8倍）** に散らばった。
   原因の多くは**定義の違い**（診断名が付いた割合／何らかの病変／骨吸収／精密診断使用時）。
   → **数字を出さずに「とても多いと言われている」で成立するなら、そちらが強い**（反証されない）。

## 1. ステップ1 — 主張の抽出

台本の**セリフ・テロップ・キャプション・サムネ文言・配信メモ**から、検証すべき医学的主張をすべて抜き出す。

### 抽出のコツ
- **1文に複数の主張が入っていることが多い。** 分解する。
  - 例:「代表的なのが慢性腎臓病。シニア猫にとても多い」→ ①PU/PDの代表的原因がCKD ②CKDはシニア猫に多い、の**2主張**
- **列挙は要素ごとに割る。**「水・尿の量と色・体重」→ 4主張（水／尿量／尿の色／体重）。
  実例として、`2026-07-22_cat-ckd` では**「色」だけが判定Cだった**。まとめて扱うと見落とす。
- **画面に出ないメモも対象。** 配信メモの前提は次弾の企画を駆動する。誤った前提を残すと誤ったシリーズが育つ。
- **数字は必ず単独の主張として立てる。** 年齢・頻度・割合・期間。→ §4
- **次弾候補メモに書かれた数字も拾う**（そのテーマ着手時に検証する宿題として記録）。

### 抽出しないもの
受診誘導（「かかりつけの先生に相談してね」）、免責、キャラのボケ、保存を促すCTA。医学的主張ではない。

## 2. ステップ2 — 一次資料への実アクセス

### 2-1. まず到達性を確認する
WebFetch は環境によって**組織のegressポリシーで 403 になる**。作業開始時に代表ホストを1つ叩いて到達性を確かめる。

- **403 が返ったら:** それは組織ポリシーによる拒否。`/root/.ccr/README.md` の規定どおり**迂回しない・リトライしない**。遮断されたホストを記録して次へ。
- **全ホストが 403 の場合:** 一次資料検証は**この環境では完了できない**。§3 の判定で **A はゼロ**になる。そのことを `03-evidence.md` の冒頭に明記し、egress開通後のチェックリストを残す（`2026-07-22_cat-ckd/03-evidence.md` が実例）。

### 2-2. 検索結果は「一次資料」ではない
WebSearch の要約・スニペットは、**検索エンジンが生成した二次的な記述**。

- 検索要約の英文を、**原文の逐語引用として台本や `03-evidence.md` に転記してはならない。**
- `03-evidence.md` では必ず列名を **「検索結果が提示した記述（原文未照合）」** とする。「引用」と書かない。
- 同趣旨が2クエリで返っても、**同一の二次ページを情報源にしている可能性**は消えない。判定はBまで。

### 2-3. 記録すること
主張ごとに: **資料名／URL／DOI／アクセス可否（✅開けた / ❌403 / ❌見つからない）／該当記述／対象種／確認日**。

## 3. ステップ3 — A / B / C 判定

| 判定 | 定義 | 台本での扱い |
|---|---|---|
| **A** | 一次資料に**実アクセスして**該当記述を確認。原文引用を保持 | 限定なしで使える（対象種の併記は必須） |
| **B** | 到達できていないが、検索結果が一次資料由来として提示した記述があり複数経路で整合。**原文照合は未了** | ヘッジ表現つきで使える。「〜と言われている」「〜のことがある」。**断定にしない** |
| **C** | 一次資料が見つからない／二次情報（ブログ・商用サイト・まとめ記事・ECサイト）しか出てこない／**反証寄りの情報がある** | **台本から削るか、主張を弱める。** 獣医師レビュー無しに公開しない |

### 判定の実務ルール
- **他人（他エージェント・他セッション）が確認した、を A にしない。** 伝聞は B。誰が・いつ確認したかを書いて引き継ぐ。
- **商用サイトしか出てこない主張は自動的に C。** 猫砂メーカー、ペット保険、フード会社のブログ、まとめ記事は根拠にならない。
- **反証寄りの情報が出たら C にして、内容をメモに残す。** その反証がしばしば**台本の別パートの説得力を上げる**（実例: 「PU/PDは早期に現れないことがある」→ だからこそ定期健診が要る）。
- 判定は主張ごと。**台本単位で「エビデンスOK」と丸めない。**

## 4. ステップ4 — 数字は個別に検証する

**年齢・頻度・割合・期間**は、最も捏造されやすく、最も反証されやすい。

| 種類 | 確認すること |
|---|---|
| **年齢**（例「7歳から」） | 指針のライフステージ区分やスクリーニング推奨開始年齢と一致するか。**独立した2系統の指針が同じ年齢を使っていれば強い** |
| **頻度**（例「年1〜2回」） | 指針の推奨の**幅の内側**にあるか。外に出ていないか。保守側に寄せるのは可 |
| **割合・有病率**（例「◯%」） | **出典間のばらつきを必ず確認する。** 実例: 猫CKDの高齢での有病率は資料により20〜50%、40%、80%と2〜4倍ばらついた |
| **量的表現**（「大半」「ほとんど」） | 割合と同じ扱い。出典に無い量的表現を足さない |

### 経験則
- **数値のばらつきが大きい主張は、リールで数値を出さない。**「とても多いと言われている」の方が、反証されず、かつ誠実。
- **数字を消すのは負けではない。** 数字を出して外すと、そのアカウント全体の信頼が落ちる。
- 逆に、**指針と一致する数字は自信を持って残す。** 検証の目的は数字を消すことではなく、根拠のある数字と無い数字を分けること。

## 5. ステップ5 — 修正提案

`03-evidence.md` に **「現状 → 修正案 → 理由」** の3点セットで書く。台本ファイルは**直接編集しない**（判断は人／親セッションが行う）。

### 修正の型
| 状況 | 対処 |
|---|---|
| C判定で、削っても情報量が落ちない | **削る**（最優先。実例: 尿の「色」） |
| C判定だが、テーマの核心 | 主張を弱める or 獣医師レビューに回す。**黙って残さない** |
| B判定で断定調 | ヘッジを足す（「〜のことがある」「〜と言われている」） |
| 条件が落ちた一般化 | 条件を戻す。**尺とキャラのトーンを壊さない範囲で**（実例:「あまり水を飲まない」→「自分から水をたくさん飲むタイプじゃない」＝語数ほぼ同じ） |
| 出典が主張に対応していない | 出典を差し替える or 用途を明記して残す |

### 「修正しないことを推奨する箇所」も必ず書く
レビューは削る作業ではない。**守るべき記述を明示的に守る**のも仕事。典型:
- 「ほかの病気のこともある」系の**鑑別ヘッジ**（1疾患に一本化して見せない）
- 数値を出していない箇所（出典間でばらつく場合、それが正解）
- 画面内免責・受診誘導・病院名/院リンクを付けない方針

## 7. 02-script.md のエビデンス欄の書き方

### ❌ 悪い例（従来形式）
```markdown
## エビデンス
- ISFM Consensus Guidelines ...: https://...
- IRIS ...: http://...
- Merck Veterinary Manual ...: https://...
```
URLが並ぶだけで**どの主張を担保するのか対応が無い**。この形式だと、実際には何も担保していない資料（例: IRIS は診断後のステージング枠組みで、有病率・多飲多尿・健診頻度のいずれも主題にしていない）が混じっても誰も気づけない。

### ✅ 良い例（主張 → 出典の対応表）
```markdown
## エビデンス
> 検証記録: 03-evidence.md（判定 A/B/C・最終確認日つき）
> 対象種: 猫。犬・他種には適用しない。

| 台本の主張 | 行 | 出典 | 判定 | 最終確認日 |
|---|---|---|---|---|
| CKDはシニア猫に多い | L17 | ISFM Consensus Guidelines, JFMS 2016 (DOI: 10.1177/1098612X16631234) | B | 2026-07-27 |
| 7歳から年1〜2回の健診（血液・尿検査） | L19 | ISFM 2016 ／ AAHA-AAFP Feline Life Stage Guidelines 2021 | B | 2026-07-27 |
| 体重減少はCKD診断に先行しうる | L18 | Freeman et al., JVIM 2016 (DOI: 10.1111/jvim.14561) | B | 2026-07-27 |

※ 参考（本台本の主張は担保しない）: IRIS = 診断後のステージング枠組み
```

### ルール
- **主張1行につき1行。** 出典だけを並べない
- **台本の行番号**を書く（改稿時にどの主張が動いたか追える）
- **判定**を書く（B が残っている＝原文照合の宿題があると一目でわかる）
- **最終確認日**を書く。**ガイドラインは改訂される**（半年〜1年で見直す）
- **対象種**を冒頭に書く
- 主張を担保しない参考資料は「参考」と明示するか、載せない

## 9. やってはいけないこと（再掲・例外なし）

1. **後付け出典** — 書いた後にそれらしいURLを添える。担保していない引用が必ず混じる
2. **未アクセス資料を「確認した」と書く** — 最も重い違反
3. **検索要約を原文引用として転記する** — 語句の改変・別ソースの混入が起こる
4. **二次情報を根拠にする** — 商用サイト、まとめ記事、ブログ、AI要約
5. **伝聞を A 判定にする** — 他エージェントの確認は B。誰がいつ確認したかを書く
6. **対象種を書かない／種を越えて一般化する** — 犬の知見を「ペット」に広げない
7. **出典に無い数字を断定する** — 特に年齢・頻度・割合
8. **C 判定を黙って残す** — 必ずフラグを立て、削るか弱めるか獣医師レビューに回す
9. **「エビデンスがある」で丸める** — 判定は主張ごと。台本単位で丸めない
10. **診断・治療方針を示す** — 判断材料までが上限。決めるのは診察した獣医師
